Scope

Hosts match themselves and all subdomains (example.com = *.example.com). One per line.

“Ask before scanning” fetches nothing from a site until you OK it: a ? on the toolbar icon means the tab is waiting, and the popup offers Scan this tab, Always scan this site (adds it to the allow-list) or Never (adds it to the deny-list). “Only the active tab” scans just the page you’re looking at; background tabs are left alone until you switch to them. The deny-list always applies.

Scanned without asking in “Ask before scanning” mode; the only sites scanned in “Only sites in the allow-list” mode.
Pages on these hosts are never scanned.
Scripts served from these hosts are skipped (analytics, ads, consent banners …).

Program scope

The scope of the bug-bounty program you're testing. When it is set, active checks only go to what it lists: the subdomain live check, “Check which endpoints are live”, “Send GET URLs to proxy” and source-map guessing. A host on neither list counts as out of scope. Out-of-scope hosts are greyed in the Domains tab, and the host menu gets an All in-scope hosts view that merges every scanned in-scope host into one list and one report.

*.acme.com = every subdomain (not acme.com itself) · acme.com = only that host · api-*.acme.com · app.acme.com:8443 · https://acme.com/api (paths count for URL checks) · 10.0.0.0/24. Out of scope wins.

Detection rules

Built-in rules. The DOM-sink rules are off by default because they are noisy; turn them on to hunt for DOM XSS.

Custom rules

One rule per line: Name | severity | regex. Severity is critical, high, medium, low or info (info rules go to Intel). Write the regex as /pattern/flags or plain. If it has a capture group, group 1 is reported. Lines starting with # are ignored.
